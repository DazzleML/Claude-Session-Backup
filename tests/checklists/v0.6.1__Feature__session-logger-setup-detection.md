Full suite: 1022 pass, 1 skipped.

## What this is

v0.6.0's `csb setup` closes with a state-aware checklist (git store, first backup, csb auto-backup plugin). v0.6.1 adds an **optional** fourth row: [claude-session-logger](https://github.com/DazzleML/claude-session-logger), the companion whose `.convo`/`.sesslog` transcripts feed csb's richer search channels and session-name enrichment. The row introduces a third visual state -- blue `[~]` "worth considering" -- deliberately distinct from yellow `[ ]` "you should do this": a human runs this checklist to confirm the distinction actually *reads* that way, and that detection matches all real install paths (GitHub marketplace AND local clone).

## Prerequisites

1. csb v0.6.1 from this working tree (`pip install -e ".[dev]"` or `python -m claude_session_backup`).
2. **A sandbox Claude dir** (never your real `~/.claude`): `<SANDBOX>/projects/C--code-demo/<uuid>.jsonl` with one or two JSONL event lines (see the v0.6.0 checklist for the fixture shape). Every command carries `--claude-dir <SANDBOX> --db <SANDBOX>/test.db`.
3. Fake plugin registries are plain JSON files under `<SANDBOX>/plugins/`:
   - `known_marketplaces.json` -- e.g. `{"dazzle-claude-plugins": {"source": {"repo": "DazzleML/claude-session-logger"}}}`
   - `installed_plugins.json` -- e.g. `{"version": 2, "plugins": {"session-logger@dazzle-claude-plugins": [{"scope": "user", "version": "0.3.6"}]}}`
4. **Windows testers:** write the registry JSON WITHOUT a BOM -- PowerShell 5.1's `Set-Content -Encoding utf8` silently prepends one (use `[System.IO.File]::WriteAllText($path, $content, (New-Object System.Text.UTF8Encoding $false))` or cmd redirection). csb tolerates a BOM'd registry (utf-8-sig read), but a BOM plus any OTHER malformation will read as "not installed" by design.
5. **Reset between sections:** delete the two registry files (and `test.db` if noted). The git repo created by setup can stay.

## High-Value Verification (~5 minutes)

### HV.1 -- Logger absent: blue [~] row with both install commands

Validates: the headline -- optional guidance, never an obligation.

- [ ] **Steps** (no `plugins/` dir in the sandbox):
  ```
  csb setup --auto --claude-dir <SANDBOX> --db <SANDBOX>/test.db
  ```
- [ ] **Expected:** checklist ends with
  ```
  [~] session logger        (optional -- richer csb search + session-name channels)
        -> claude plugin marketplace add "DazzleML/claude-session-logger"
        -> claude plugin install session-logger@dazzle-claude-plugins
  ```
  The csb `auto-backup plugin` row above it is `[ ]` (also absent) -- **eyeball check:** in a real terminal, `[~]` renders blue and `[ ]` yellow, and the difference reads as "optional vs to-do" at a glance. A tester who can't tell them apart is a finding.
- [ ] **Why this matters:** The whole point of `[~]` is that optional never masquerades as required; only a human can judge the visual semantics.

### HV.2 -- Logger installed: green [x], zero re-instruction

- [ ] **Steps:** write both registry files (marketplace + plugin entries for the logger, per Prerequisites), re-run the same `csb setup --auto`.
- [ ] **Expected:** `[x] session logger        (session-logger@dazzle-claude-plugins installed)`; no `[~]`, no `claude plugin` commands for the logger anywhere in the output.
- [ ] **Why this matters:** v0.6.1 exists because setup once told the owner to install a plugin that was already installed -- regression here is the original sin.

### HV.3 -- Local-clone install path counts as done

Validates: Quick Start "Option 2" (clone + `claude plugin marketplace add "./"`) registers the same plugin key without the GitHub marketplace entry.

- [ ] **Steps:** registry files with ONLY `installed_plugins.json` containing the logger plugin key (no `dazzle-claude-plugins` in `known_marketplaces.json`); re-run setup.
- [ ] **Expected:** `[x] session logger` -- plugin presence alone is done; no marketplace-add nag for a user who deliberately installed from a local clone.
- [ ] **Why this matters:** Both documented install routes must satisfy the detector; punishing the local-clone route with a permanent `[~]` would teach users to ignore the checklist.
