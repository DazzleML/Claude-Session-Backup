# Human Test Checklist: source-agnostic + multi-term `csb search -d/-D`

**Target version:** v0.5.1
**Ships with commit:** `v0.5.1: fix/feat: source-agnostic + multi-term csb search -d/-D` (TBD -- pre-commit)
**Companion automated tests:** 17 new -- `tests/test_search.py` (7 source-agnostic dir-scope engine tests incl. start-folder tiebreak + uppercase `--session` prefix, 2 FTS5 dir-scope multi-term tests incl. regex, 1 enumerator folders-opt-in contract) + `tests/test_commands.py` (7 `cmd_search` wiring tests). The 9 pre-existing FTS5 dir-scope tests in `tests/test_search.py` now pin `--source fts5`. Full suite: 969 pass, 1 skipped.

## What this is

v0.5.0 shipped multi-term boolean search and (separately) FTS5 directory-scope ranking, but the two never composed and directory-scope was FTS5-only. This release makes `csb search -d/-D` accept **multiple terms** AND **any `--source`**. The default `csb search <term> -d .` now ranks by folder-usage (finds every session active in the folder) instead of FTS5 file-op strength; `--source fts5` keeps the strength ranking. A human runs this to confirm the real CLI behaves across sources/shells and that the default-behavior change reads sensibly.

## Prerequisites

1. Windows or Linux; `csb` installed from this working tree (`pip install -e ".[dev]"`), or run via `python -m claude_session_backup`.
2. A populated csb index (run `csb backup --no-commit` at least once). `csb search` is **read-only** with respect to your sessions -- it opens the index and reads folder_usage / session_sources; it does not modify transcripts. Safe to run against your real `~/.claude`.
3. Pick a folder you've actually worked in with Claude Code (substitute for `<DIR>` below) and two terms you know appear together in some session there (substitute `<T1>` / `<T2>`). The examples use this repo's folder and common words.
4. **Reset between sections:** none needed -- every step is read-only. Re-run any step freely.

All commands below are `csb` invocations and are **shell-agnostic** (no env vars, redirection, or file ops), so a single code block serves cmd.exe, PowerShell, and POSIX identically unless noted.

## High-Value Verification (~5 minutes)

### HV.1 -- The reported bug: multi-term + `-d` no longer errors

Validates: the exact command from the bug report runs instead of printing "multiple search terms are not supported with -d/-D".

- [ ] **Steps:**
  ```
  csb search --match all "SC:N" "SI:N" "SA:N" -d .
  csb search "SC:N" "SI:N" "SA:N" -d . --match all
  ```
- [ ] **Expected:** Both run and exit 0. Either hits are shown, or a plain `No content matches for "SC:N" "SI:N" "SA:N" (--match all)`. **NOT** the old `Error: multiple search terms are not supported...`. Flag order (before/after the terms) makes no difference.
- [ ] **Why this matters:** This is the literal user-reported failure; if it still errors, the fix didn't ship.

### HV.2 -- Directory-scope accepts a non-FTS5 source

Validates: `-d` with `--source jsonl|convo|sesslog` is allowed (was rejected as "incompatible").

- [ ] **Steps:**
  ```
  csb search "<T1>" -d <DIR> --source jsonl
  csb search "<T1>" -D <DIR> --source convo
  ```
- [ ] **Expected:** Both exit 0. No `Error: -d/-D directory-scope is incompatible with --source ...`. Results (if any) are drawn from the named channel.
- [ ] **Why this matters:** "Any `--source` should be valid" is the core requirement; a rejection here means the guard removal regressed.

### HV.3 -- Default `-d` finds folder sessions across sources

Validates: the default (no `--source`) uses the folder_usage path and surfaces sessions active in the folder regardless of FTS5 indexing.

- [ ] **Steps:**
  ```
  csb search "<T1>" -d <DIR>
  ```
- [ ] **Expected:** Exit 0. Sessions that were active under `<DIR>` and mention `<T1>` are listed, ordered most-active-in-folder first. Hits may come from `.convo` / `.sesslog` / `jsonl` (check the source label per hit) -- not only FTS5-indexed sessions.
- [ ] **Why this matters:** This is the behavior change -- the default now reaches non-FTS5 content. If it only ever shows FTS5 hits, the source pin wasn't removed.

### HV.4 -- Explicit `--source fts5` still gives file-op strength ranking

Validates: the precise mode is preserved and shows the `[N file-ops, strength=S]` suffix.

- [ ] **Steps** (needs FTS5 built: `csb update build-fts5` for the project):
  ```
  csb search "<T1>" -d <DIR> --source fts5
  ```
- [ ] **Expected:** Exit 0. Session headers carry the `[N file-ops, strength=S]` suffix and are ordered by strength DESC. Only FTS5-indexed sessions appear.
- [ ] **Why this matters:** Retiring this ranking silently would be a regression; the user chose to preserve it.

### HV.5 -- `--match all` vs `--match any` under `-d`

Validates: the boolean combiner works with directory-scope.

- [ ] **Steps** (pick `<T1>`/`<T2>` where some folder session has both, another has only one):
  ```
  csb search "<T1>" "<T2>" -d <DIR> --match all
  csb search "<T1>" "<T2>" -d <DIR> --match any
  ```
- [ ] **Expected:** `all` returns only sessions containing **both** terms; `any` returns a superset (sessions with at least one). `any` count >= `all` count.
- [ ] **Why this matters:** Confirms the term qualification (not just "no error") is actually applied per session.

### HV.6 -- `--min-strength` degrades to a note, not a failure

Validates: raising `--min-strength` under a non-FTS5 source prints a note and proceeds.

- [ ] **Steps:**
  ```
  csb search "<T1>" -d <DIR> --min-strength 2
  ```
- [ ] **Expected:** A stderr line `Note: --min-strength applies only to --source fts5 (file-op strength ranking); ignored for --source auto.` then normal results. Exit 0. With `--source fts5 --min-strength 2` there is **no** note.
- [ ] **Why this matters:** Flags should degrade gracefully; a hard error or silent pretend-filter would both be wrong.

After these pass, the feature shipped. Sections below cover `-d` vs `-D` scoping, ordering, `--session`, and rendering.

## Section 1: scoping semantics

### 1.1 `-d` (descendants) vs `-D` (folder-only)

- [ ] **Steps:** Choose `<PARENT>` that has sessions active both directly in it and in a subfolder.
  ```
  csb search "" -D <PARENT> --limit 50
  csb search "" -d <PARENT> --limit 50
  ```
  (Empty query = match-all within scope; use `--only sessions` to compare session sets cleanly:)
  ```
  csb search "" -D <PARENT> --only sessions
  csb search "" -d <PARENT> --only sessions
  ```
- [ ] **Expected:** `-d` returns a superset of `-D` -- it includes sessions whose only folder-usage under `<PARENT>` is in a **subfolder**; `-D` excludes those.
- [ ] **Check:** No session appears under `-D` that isn't also under `-d`.

### 1.2 Bare `.` and relative paths resolve

- [ ] **Steps** (run from inside a project folder):
  ```
  csb search "<T1>" -d .
  ```
- [ ] **Expected:** `.` resolves to the current working directory; results are scoped to sessions active there.

## Section 2: ordering & filters

### 2.1 Default ordering is folder-usage DESC

- [ ] **Steps:**
  ```
  csb search "<T1>" -d <DIR> --only sessions
  ```
- [ ] **Expected:** Sessions that were **most active** in `<DIR>` appear first. (Contrast: without `-d`, plain `csb search <T1>` orders by last-used time.)

### 2.2 `--session` narrows the scoped set

- [ ] **Steps** (grab a UUID prefix from a prior result):
  ```
  csb search "<T1>" -d <DIR> --session <prefix>
  ```
- [ ] **Expected:** Only the matching session(s) remain; still scoped to `<DIR>`.

### 2.3 `--deleted` interplay

- [ ] **Steps:**
  ```
  csb search "<T1>" -d <DIR> --deleted only
  csb search "<T1>" -d <DIR> --deleted all
  ```
- [ ] **Expected:** `only` restricts to deleted sessions active in the folder; `all` shows live + deleted together. Exit 0 in both.

## Section 3: rendering & output modes

### 3.1 `--json` for a scoped multi-term search

- [ ] **Steps:**
  ```
  csb search "<T1>" "<T2>" -d <DIR> --match any --json
  ```

  Pretty-print (cross-shell):
  ```
  csb search "<T1>" "<T2>" -d <DIR> --match any --json | python -m json.tool
  ```
- [ ] **Expected:** Valid NDJSON; each record carries `session_id`, `source_type`, matched text. No stray banner lines mixed into the JSON stream (the `--min-strength` note, if any, goes to stderr, not stdout).

### 3.2 `--source fts5` strength suffix renders cleanly

- [ ] **Steps:**
  ```
  csb search "<T1>" -d <DIR> --source fts5 -ff
  ```
- [ ] **Expected:** `[N file-ops, strength=S]` suffix present and readable; folder list (from `-ff`) shows without column cramping or trailing whitespace on your terminal width.

## What the automated tests DON'T cover

- **Real folder_usage data at scale** -- mocks insert a handful of rows; only a real index shows whether usage_count ordering *feels* right across dozens of sessions.
- **Cross-source hit quality** -- whether the `.convo`/`.sesslog`/`jsonl` a session resolves to actually holds the terms in real transcripts (mocks use tiny fixtures).
- **Terminal rendering** -- the `[N file-ops, strength=S]` suffix, folder-list columns, color, and width behavior on a real console (Windows cp1252 vs a POSIX UTF-8 term).
- **The `--min-strength` note on stderr vs stdout** -- that it doesn't corrupt a `--json` pipe in a real shell.
- **Discoverability** -- does `csb search -h` make the new source-agnostic `-d/-D` behavior and the `--source fts5` strength mode understandable?
- **The default-behavior change feel** -- a returning user who relied on the old FTS5-strength default: is the new folder-usage default an obvious improvement or a surprise? (Read the CHANGELOG "Behavior change" note and judge.)
