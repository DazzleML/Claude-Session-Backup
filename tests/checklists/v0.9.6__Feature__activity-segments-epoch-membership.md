# v0.9.6 -- Feature -- activity segments: epoch membership from real timelines (#80)

Hand-runnable companion to `tests/test_activity_segments.py` (22 automated tests). Verifies on a real store what mocks approximate: epoch rosters built from each session's activity timeline, so reactivating a session no longer erases it from the epochs it really lived in.

**Legend** (for external testers): #80 = the GitHub issue this implements; "segment"/"sitting" = one contiguous run of activity in a session's transcript, split where event timestamps gap by more than 10 minutes; "epoch" = the span between two machine restarts (`last`, `last~N`); "point membership" = the old rule (a session belonged only to the epoch holding its final activity); "snapshot-union" = roster rows proven by a shutdown boundary snapshot rather than indexed activity.

## Prerequisites

- csb at the version carrying this checklist; any prior index is fine (the v9 schema migration applies on first use -- you may see one `csb: migrated DB schema to v9` line).
- One `csb backup` (or `csb backup --no-commit`) run AFTER upgrading -- this records timelines for every live session in one pass.

## 1. Migration + backfill happen quietly

- [ ] First csb command after upgrading prints the one-line v9 migration notice (or nothing, if already migrated). No errors.
- [ ] After one backup: `python -c "import sqlite3; c=sqlite3.connect(r'<claude-dir>\session-backup.db'); print(c.execute('SELECT COUNT(*), COUNT(DISTINCT session_id) FROM session_activity').fetchone())"` -> hundreds-to-thousands of rows across roughly your active-session count.

## 2. The founding scenario, on your own history

- [ ] `csb set list` -> pick an epoch a few restarts back (`last~N`).
- [ ] `csb set show last~N` -> sessions you RESUMED SINCE that epoch still appear in it (pre-#80, resuming moved them out -- deep epochs thinned to empty and the roster walked past them).
- [ ] An epoch that used to fall through as empty now holds members (the walk disclosure `-- empty; showing the nearest epoch with members --` should now be rare: only genuinely idle periods).

## 3. Per-epoch honesty (in-window values)

- [ ] Pick a session appearing in TWO epochs' rosters. Its `N msgs` differs between them (each epoch counts its own sittings), and both are smaller than the lifetime count `csb show <session>` reports.
- [ ] Its gap column (`Xh before shutdown`) reflects that epoch's last activity -- not the session's global last-active time.
- [ ] `csb set show <epoch> --json` -> those members carry `"segment_backed": true`.

## 4. Absence stays proven

- [ ] Find a session active in an old epoch and again recently (section 3's session works). Check an epoch BETWEEN those two periods where you know it sat closed: it does not appear there.

## 5. Snapshot-union rows

- [ ] `csb set show last --open` -> only `[open at shutdown]` members (unchanged behavior; badge rows now arrive via the materializer).
- [ ] IF you have a purged session that a boundary snapshot proves was open at some shutdown: its roster row shows `[open at shutdown -- no indexed activity in this window]`, appended after the activity-ordered members, included in the session count. (Skip if no such session exists -- the automated end-to-end test covers the mechanics.)

## 6. The other views

- [ ] `csb set show boot` -> message counts are since-boot values, not lifetime totals; tiers ([running]/[exited]) unchanged.
- [ ] Purged-row archaeology still works: `csb set show <old-epoch>` renders `[purged]` rows exactly as before (point membership -- their transcripts are gone, honestly disclosed).
- [ ] `csb resume --set <epoch> <N>` addresses the row you just read (the same materializer serves show and resume).

## 7. Speed spot-checks

- [ ] `csb set show last~1` completes in ~the same wall time as before (segments add ~13ms; the event-log fence read dominates).
- [ ] A backup completes in roughly its usual time (the fold measured ~+8% on the parse; see `bench_segments_scan.py` in one-offs for the method and numbers).

## What the mocks don't cover

- Your real epoch history: dozens of epochs, purged rows, boundary snapshots accumulated across actual restarts.
- The migration against a production-sized, production-aged index.
- Whether in-window counts MATCH YOUR MEMORY of what you did in an epoch -- the only test for semantic trust.
- Rendering: the long snapshot-union mark wrapping on narrow consoles.
