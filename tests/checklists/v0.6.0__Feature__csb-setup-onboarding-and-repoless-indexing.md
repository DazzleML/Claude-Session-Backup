## What this is

An RDP crash killed two live sessions on a machine whose rebuilt `~/.claude` was never `git init`-ed. Every backup -- manual and hook-fired -- failed silently at the git precondition, so the index stayed empty and `csb list` / `csb scan` answered "No sessions found." with the transcripts sitting intact on disk. This release decouples *indexing* from *git* AND inverts the onboarding philosophy: protection is the rule, and `csb setup` (guided / `--auto`) is the required path to it. A repo-less dir shows a NO BACKUP PROTECTION banner on EVERY interactive run until a repo exists or the user records an explicit `csb setup --index-only` sign-off. `csb backup --no-commit` works repo-less (index-only, loudly non-protective), empty states diagnose themselves, `csb _check` + the hook warn instead of erroring into a log file, and `csb status` says the way out. A human runs this because the whole feature IS console UX -- warning prominence, hint wording, and "does the message actually tell me what to type next" can't be judged by asserts.

## Prerequisites

1. Windows or Linux; run the working tree via `python -m claude_session_backup` from the repo root (or `pip install -e ".[dev]"` and use `csb`).
2. **A sandbox Claude dir, NOT your real `~/.claude`** -- these steps exercise a repo-less dir and a throwaway index. Build it (any shell; adjust paths):
   - Create `<SANDBOX>/projects/C--code-demo/`
   - Copy any real session JSONL into it (e.g. one file from `~/.claude/projects/<slug>/<uuid>.jsonl`), keeping the `<uuid>.jsonl` name
   - Do **NOT** `git init` the sandbox
   - Every command below passes `--claude-dir <SANDBOX> --db <SANDBOX>/test.db`, so your real index is never touched
3. **Reset between sections:** delete `<SANDBOX>/test.db` to return to the "index never built" state. Nothing else accumulates.

## High-Value Verification (~5 minutes)

### HV.0 -- `csb setup --auto`: zero-to-protected in one command

Validates: AC-S2 -- the headline onboarding path.

- [ ] **Steps** (fresh sandbox, no test.db, no git repo):
  ```
  csb setup --auto --claude-dir <SANDBOX> --db <SANDBOX>/test.db
  csb status --claude-dir <SANDBOX> --db <SANDBOX>/test.db
  ```
- [ ] **Expected:** setup prints the resolved dir, `Initialized git repository`, the `.gitattributes` line, `First backup complete`, and a state-aware `Setup checklist:` -- `[x] git backup store` and `[x] first backup` checked, `[ ] auto-backup plugin` with the `claude plugin ...` commands (the sandbox has no plugin registries). Exit 0, zero prompts. `status` shows `Git repo: yes` and the indexed session. A repeat `csb setup` run says "nothing to set up" with the same checklist. **Eyeball check:** no already-done item is accompanied by a command telling you to do it again.
- [ ] **Why this matters:** This is THE onboarding promise of 0.6.0; if it prompts, fails, or half-configures, the release headline is wrong.

### HV.0b -- The nag: NO BACKUP PROTECTION banner on every run until resolved

Validates: AC-S4 + AC-S3 -- unprotected-and-unacknowledged cannot be quiet.

- [ ] **Steps** (RESET first: delete `<SANDBOX>/.git` and `<SANDBOX>/session-backup-config.json`):
  ```
  csb list --claude-dir <SANDBOX> --db <SANDBOX>/test.db     (run TWICE)
  csb setup --index-only --claude-dir <SANDBOX> --db <SANDBOX>/test.db
  csb list --claude-dir <SANDBOX> --db <SANDBOX>/test.db
  ```
- [ ] **Expected:** Both first runs print the `NO BACKUP PROTECTION` banner (stderr) naming `csb setup` and `csb setup --index-only`. The `--index-only` run states the consequences and (non-TTY) records the sign-off -- in a real terminal it asks you to TYPE `index-only` back. The final `list` shows NO banner. **Eyeball check:** is the banner impossible to miss, and does the typed confirmation feel like real informed consent rather than a shrug?
- [ ] **Why this matters:** The every-run nag and the signed exception ARE the philosophy; string asserts prove presence, only a human judges loudness and consent quality.

### HV.1 -- The crash scenario end-to-end: dead end becomes 2-command recovery

Validates: AC2/AC3 -- the exact reported failure ("csb list shows nothing after a crash") now self-diagnoses and recovers.

- [ ] **Steps** (fresh sandbox, no test.db):
  ```
  csb list --claude-dir <SANDBOX> --db <SANDBOX>/test.db
  csb backup --no-commit --claude-dir <SANDBOX> --db <SANDBOX>/test.db
  csb list --claude-dir <SANDBOX> --db <SANDBOX>/test.db
  ```
- [ ] **Expected:** First `list`: `No sessions found.` **plus** `Note: the csb index is empty -- 1 session file exist on disk but nothing has been indexed yet.` and both backup forms named. The `backup --no-commit`: exit 0, `Scanned 1 sessions...`, and two `[index-only]` stderr lines pairing "Indexed" with "NO backup protection". Second `list`: the session renders normally.
- [ ] **Why this matters:** This is the user-reported incident replayed; if the hint or the repo-less index build fails, the release's reason to exist is gone.

### HV.2 -- Bare `csb backup` still refuses, and names both ways out

Validates: AC5 -- protection semantics unchanged; error now teaches.

- [ ] **Steps:**
  ```
  csb backup --claude-dir <SANDBOX> --db <SANDBOX>/test.db
  ```
- [ ] **Expected:** Exit 1. Stderr: `not a git repository`, the `git -C ... init` line, AND the new `Or run csb backup --no-commit ...` line. Nothing indexed if run on a fresh db.
- [ ] **Why this matters:** Index-only must be opt-in; a bare `backup` silently degrading to "no protection" would be worse than the original bug.

### HV.3 -- Warning prominence judgment call (human-only)

Validates: the `[index-only]` warning cannot be misread as success.

- [ ] **Steps:** Re-run HV.1's backup command; also with `--quiet`.
- [ ] **Expected:** In both runs the `[index-only] ... NO backup protection` lines appear (stderr survives `--quiet`). **Eyeball check:** in your terminal's colors/wrapping, is the warning visually impossible to miss next to `Scanned N sessions`? Would a tired you at 2am notice this was not a backup?
- [ ] **Why this matters:** Tests assert the string exists; only a human can judge if it *reads* loud enough. If it doesn't, that's a finding.

## Full Verification (~10 more minutes)

### FV.1 -- Path-scan redirection tip

Validates: AC4 -- the "scanned my checkout, session ran elsewhere" mental-model gap.

- [ ] **Steps** (index built, i.e. after HV.1):
  ```
  cd <any folder with NO sessions, e.g. a temp dir>
  csb scan . --claude-dir <SANDBOX> --db <SANDBOX>/test.db
  ```
- [ ] **Expected:** `No sessions found.` plus `Tip: 1 session exists under other folders -- try csb list -n 5 or csb scan -d <parent-folder>.`
- [ ] **Why this matters:** This is the second half of the incident -- scan in the "wrong" folder must redirect, not dead-end.

### FV.2 -- Hints know when to shut up

Validates: AC3 (no-files case) + AC7 (machine-readable outputs).

- [ ] **Steps:** (a) point `--claude-dir` at an empty dir with only `projects/` and a fresh db -> `csb list`; (b) HV.1 first-state `csb list --json`; (c) FV.1 scan with `--json` and with `--quiet`.
- [ ] **Expected:** (a) classic `No sessions found.` with NO "index is empty" hint (there is genuinely nothing). (b) pure `[]` JSON, no hint text. (c) no Tip under `--json`/`--quiet`.
- [ ] **Why this matters:** A hint that fires wrongly (or corrupts JSON pipelines) converts helpful into noisy; suppression paths are where that regresses.

### FV.3 -- Repo-less `_check` + status advice

Validates: the silent-failure channel now speaks.

- [ ] **Steps:**
  ```
  csb _check --claude-dir <SANDBOX> --db <SANDBOX>/fresh.db
  csb status --claude-dir <SANDBOX> --db <SANDBOX>/fresh.db
  ```
- [ ] **Expected:** `_check`: exit 10 (gap), summary says `not a git repository (backups are failing)` and recommends `csb backup --no-commit` and names `csb setup` for real backups. `status`: `Git repo:      NO` followed by the parenthetical advice lines (`csb setup` / git init to enable; `--no-commit` indexes without git).
- [ ] **Why this matters:** `_check` output becomes the hook's systemMessage verbatim -- its wording is the first thing a crash victim sees at next session start.

### FV.4 -- Upgrade path: repo appears later

Validates: AC8 -- index-only is a stepping stone, not a trap.

- [ ] **Steps:** `git init` the sandbox by hand OR via `csb setup --auto` (add `git config user.email/name` if your global config lacks identity), then run bare `csb backup --claude-dir <SANDBOX> --db <SANDBOX>/test.db` and `csb status ...`.
- [ ] **Expected:** Backup exits 0, commits appear (`Noise commit:`/`User commit:`), no `[index-only]` lines. Status shows `Git repo: yes` and no advice block.
- [ ] **Why this matters:** The recommended recovery ends with `git init`; if the transition double-indexes, fails to commit pre-indexed sessions, or keeps warning, the story breaks at its last step.

### FV.5 -- Hook fallback (log-level check)

Validates: hook runs stop dying at the precondition.

- [ ] **Steps:** With the repo-side hook script: `echo {"hook_event_name":"SessionEnd"} | python hooks/scripts/backup-hook.py` while `CLAUDE_DIR=<SANDBOX>` is set (shell-specific env syntax; PowerShell: `$env:CLAUDE_DIR="<SANDBOX>"`). Then read `<SANDBOX>/csb-logs/backup-SessionEnd.log`.
- [ ] **Expected:** The log gains `[index-only] no git repo -- falling back to backup --no-commit ...` and the spawned run's `[index-only]` stderr -- NOT the old bare `Error: ... is not a git repository.` pair.
- [ ] **Why this matters:** The original incident's two days of silence lived exactly here; the log line is the difference between "failing quietly" and "degrading honestly".

## What mocks don't cover

- REAL interactive prompts in a live terminal (HV.0b, and `csb setup` without --auto): automated tests monkeypatch `_ask`/`_interactive`; a human must feel the Y/n defaults and the typed `index-only` confirmation.

- Warning *prominence* and hint *wording* in a real terminal (HV.3) -- string asserts can't judge readability.
- Real `git init` transition on a real filesystem (FV.4) -- the automated repo-less tests mock `is_git_repo`.
- The detached hook spawn writing to the real log file across process boundaries (FV.5) -- hook tests fake `Popen`.
- Windows vs POSIX path rendering inside the new messages (`git -C <full path> init` with spaces/backslashes).
