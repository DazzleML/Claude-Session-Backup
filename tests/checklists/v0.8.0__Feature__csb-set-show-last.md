## What this is

`csb set show last` reconstructs which sessions were active before the machine's most recent shutdown -- the "Windows Update restarted my 15 windows" recovery. Fences come live from the Windows System event log; membership from the index's activity timestamps. Read-only: no hooks, no storage, no schema change. This checklist covers what mocks cannot: your real event log, a real post-restart roster judged against memory, real console rendering, and the PowerShell dependency.

## High-Value Verification (~5 minutes)

### HV.1 -- The roster matches your memory

- [ ] **Steps:** `csb set show last`
- [ ] **Expected:** A header naming your machine's real last shutdown (date, UTC time, cause), then a numbered roster of sessions in activity order, each with `start at:` and a `[csb resume <name>]` hint.
- [ ] **Judge it against memory:** were those the sessions you had going before the restart? Missing ones that were idle longer than the window are the known limit -- but a session you KNOW was active shortly before the restart must be present.
- [ ] **Why this matters:** the whole feature is this roster being trustworthy; only a human with memory of the restart can judge it.

### HV.2 -- The shutdown cause is right

- [ ] **Steps:** compare the header's cause label against what actually happened (`clean shutdown` / `UNEXPECTED shutdown` / `restart initiated by a process (update/restart)`).
- [ ] **Expected:** a Windows Update restart shows `initiated by a process`; a power cut shows `UNEXPECTED`.
- [ ] **Why this matters:** the label is read from 6008/1074 events; only real history exercises it.

### HV.3 -- A resume hint actually resumes

- [ ] **Steps:** copy one row's `csb resume <name>` and run it in a terminal positioned where you want the session.
- [ ] **Expected:** the session opens in THAT terminal. csb spawned no window, no tab.
- [ ] **Why this matters:** the roster's promise is that reclaiming is one paste per window, with terminal choice staying yours.

### HV.4 -- Honest language

- [ ] **Steps:** read the header and rows.
- [ ] **Expected:** the output says "active ..." and "activity order -- open order is not tracked". Nowhere does it claim a session "was open".
- [ ] **Why this matters:** activity is evidence, not proof; the display discipline is an explicit AC.

## Section 1: windows and fences

- [ ] `csb set show last --window 24` -- roster shrinks (or empties) vs the default; header switches to "active within 24h of shutdown (--window)"
- [ ] `csb set show last --window 0.1` -- almost certainly empty; the empty state names `--window` as the lever, no traceback
- [ ] If your machine's last restart was an update: check the event log shows the double shutdown/boot cycle (`Get-WinEvent -FilterHashtable @{LogName='System'; ID=6005,6006} -MaxEvents 6`) and confirm the header shows ONE fence and a sane multi-day window -- not a seconds-wide one (the cluster-collapse fix)
- [ ] On a machine/VM with a freshly cleared System log: `csb set show last` reports "No shutdown fence found" gracefully

## Section 2: index interplay

- [ ] Run `csb backup`, then `csb set show last` -- no freshness advisory on stderr
- [ ] The purged marker: if `csb list --deleted only` has sessions in the window, they appear `[purged -- resume will offer restore-from-git]`, and their resume hint walks the restore prompt
- [ ] `csb set show last --json | python -m json.tool` -- parses; envelope has `epoch.cause`, `epoch.window_source`, numbered `members`; any stderr advisory stays OFF stdout

## Section 3: console rendering

- [ ] cmd.exe (cp437), PowerShell (cp1252), and Windows Terminal: session names with any non-ASCII render without `UnicodeEncodeError` (errors=replace may show `?` -- acceptable)
- [ ] Narrow terminal (~80 cols): rows stay two lines each, readable, no phantom wrapped fragments
- [ ] Piped: `csb set show last | more` stays aligned, no color codes garbling the pager

## Section 4: off-Windows behavior (WSL or any Linux box)

- [ ] `csb set show last` exits 1 with a clear "Windows-only in this version" message naming the epic -- no traceback

## What the mocks don't cover (why this checklist exists)

- The REAL event log: 1074-heavy update histories, log rotation, domain-policy quirks
- Your memory of the restart -- the only oracle for roster completeness
- PowerShell availability variants (Constrained Language Mode, PATH oddities)
- Console codepages and pagers
- The feel: is the default window right on a machine with a heavy multi-window life? (The aktuldjr validation run.)
