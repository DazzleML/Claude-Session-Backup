## What this is

`csb set show boot` = everything active since startup, with `[running]` / `[no exit observed]` / `[exited]` tiers -- the view between `current` and `last`. Plus the resume grammar change: `--set` replaces the `set` sentinel. This checklist covers the real-machine half: real tier counts against your actual boot, the reclaim loop under the new grammar, and the collision that is now supposed to be gone.

## High-Value Verification

### HV.1 -- The boot view tells your day's story

- [ ] **Steps:** `csb set show boot`
- [ ] **Expected:** every session you've touched since the machine booted -- open ones `[running]`, ones you closed `[exited]`, in activity order; the counts line (`N sessions: R running, U no exit observed, E exited`) matches your memory of the day. Compare against `csb set show current` -- boot ⊇ current.
- [ ] **Why:** only you know what today actually looked like; 17-sessions-4-running-13-exited was the live result on the dev box, but yours is the test.

### HV.2 -- `[exited]` appears and disappears correctly

- [ ] **Steps:** open a scratch session, exit it cleanly, `csb set show boot`.
- [ ] **Expected:** the scratch session shows `[exited]` (it ran this boot; its entry was erased). It does NOT appear in `csb set show current`.
- [ ] **Why:** the tier only this view can show, exercised end to end through real hooks.

### HV.3 -- The `--set` grammar, hands on

- [ ] **Steps:** `csb resume --set` (bare) -> read the menu -> `csb resume --set 2` in a terminal you choose. Then `csb set new TODAY --from boot` -> `csb resume --set TODAY`.
- [ ] **Expected:** bare `--set` lists `last`'s reclaimable members; `--set 2` launches member 2 in THIS terminal; the named-set menu round-trips. (`csb set rm TODAY` after.)
- [ ] **Why:** the reclaim loop under the new grammar, muscle-memory check included.

### HV.4 -- The collision is gone

- [ ] **Steps:** `/rename` a scratch session to exactly `set`, then `csb resume set`.
- [ ] **Expected:** it RESUMES that session -- no menu, no grammar error. (Rename it back after.)
- [ ] **Why:** this is the entire reason `--set` exists; only a real session named `set` proves it.

### HV.5 -- Hookless honesty (WSL/VPS or `--claude-dir` on a hookless store)

- [ ] **Steps:** `csb set show boot` against a store with no registry activity this boot.
- [ ] **Expected:** rows carry NO liveness tags; footer says "exit detection unavailable (no hook activity observed this boot)".
- [ ] **Why:** the never-a-guessed-tag rule under real conditions.

## Sections

- [ ] `csb set show boot --window 2` -- narrows to the last 2h with gaps, header says "before now"
- [ ] `csb set show boot --open` -- rc 2, names `csb set show last --open`
- [ ] `csb set new boot x` / `csb set new last~1 x` / `csb set new 2026-8-9 x` -- all rejected as reserved; `csb set new 2026-8-9__topic x` legal
- [ ] `csb resume --set NOPE 1` -- "No set named"; `csb resume` bare -- rc 2 usage with the three forms
- [ ] `-- --fork-session` after `--set N` forwards (check the fork opens)
- [ ] Old form `csb resume set 2` now treats "set" as a query (errors unless you have a session named set) -- confirm the error is comprehensible
