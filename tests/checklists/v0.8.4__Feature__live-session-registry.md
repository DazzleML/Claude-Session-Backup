## What this is

csb's hooks now write one file per session on start and erase it on clean close -- so `csb set show current` knows what is open right now, leftovers are crash evidence, `csb set new NAME --from current` freezes the group, bare `csb resume set NAME` lists what is left to reclaim, and `csb resume` warns before putting a second client on a live transcript. This checklist covers what mocks cannot: the real hook firing in real sessions, a real reboot crossing the boundary sweep, and the guard prompting a real human.

## High-Value Verification

### HV.1 -- Open sessions appear; closed sessions disappear

- [ ] **Steps:** with 2+ freshly-restarted sessions open, `csb set show current`. Then cleanly exit ONE session and re-run.
- [ ] **Expected:** all restarted sessions listed `[running]` in the order you opened them; after the exit, that session is GONE from the roster (its clean close erased the entry).
- [ ] **Why:** the whole mechanism -- write on start, erase on close -- observed live. Automated tests fake the hook payloads; only real sessions prove Claude Code delivers them.

### HV.2 -- The reclaim loop end to end

- [ ] **Steps:** `csb set new TONIGHT --from current` -> exit two sessions -> `csb resume set TONIGHT` -> reclaim one via `csb resume set TONIGHT <N>` in a terminal you choose -> `csb resume set TONIGHT` again.
- [ ] **Expected:** the menu lists only closed members with their canonical numbers (gaps for open ones); after reclaiming, that member leaves the menu ON ITS NEXT START (the new session registers); the counts line reads correctly throughout.
- [ ] **Why:** this is the epic's promise assembled: freeze the group, lose some, get them back one terminal at a time.

### HV.3 -- The live guard, as a human

- [ ] **Steps:** `csb resume <name-of-a-session-that-is-open>` in a fresh terminal. Decline at the prompt. Then try `csb resume <same> -- --fork-session`.
- [ ] **Expected:** a prompt naming the session (and pid when process-verified); declining launches nothing, exit 0; the fork form runs with NO prompt and opens a branch.
- [ ] **Why:** two clients on one transcript is the hazard; the prompt wording and the fork exemption need human eyes.

### HV.4 -- The boundary sweep (REAL REBOOT)

- [ ] **Steps:** with sessions open, note `csb set show current`. Reboot without closing them. After login, start any session, then: `csb set show current` (should be empty or only the new session), `csb set show last` (rows badged `[open at shutdown]` matching what you had open), `csb set show last --open`.
- [ ] **Expected:** pre-reboot entries swept into the snapshot; `last` badges exactly the sessions that were open; `--open` narrows to them with canonical indices.
- [ ] **Why:** the sweep classifies against the real boot fence; no test can cross a real reboot.

### HV.5 -- Crash evidence

- [ ] **Steps:** kill a session's terminal window outright (no clean exit). `csb set show current`.
- [ ] **Expected:** the session stays listed as `[no exit observed]` (its entry survives; process verification finds nothing). This is correct: the leftover IS the evidence.
- [ ] **Why:** the design's central asymmetry, observed rather than asserted.
