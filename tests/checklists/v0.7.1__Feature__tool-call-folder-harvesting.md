**Revision 4** (after the third pass returned HOLD on one new SEV-1).
Fixed and covered here: quoted `cd` targets truncating at spaces (4d.8 --
the fragment corrupted the cd-fact ranking itself), error messages leaking
a Python identifier (4d.9), all-dots components defeating the existence
probe (4d.10), and the F1 scratch-prominence escape with its aggregate
reporting (4d.11).

## What this is

`csb scan <repo>` used to find nothing for a repository a session had spent its
life editing, and `csb show` listed a single working directory. This release
harvests work locations from **tool-call arguments** instead of only the
session's `cwd`, and changes what `usage_count` measures.

Two things here are hard to verify with mocks and easy to get wrong:

1. **The numbers are judgments, not just data.** A folder ranking too high or
   too low still "passes" every assertion. Only a human who knows what they
   actually worked on can say whether the ranking is *true*.
2. **The precision rules were tuned against real transcripts.** Synthetic
   fixtures can't produce the junk that motivated them (`2>/dev/null`,
   unexpanded `$VAR`, embedded source-code literals). Running this against
   your own vault is the real test.

Run this on a machine with real session history. An empty index proves nothing.

## Prerequisites

1. **Windows, macOS, or Linux.** Several sections are Windows-specific and
   marked; the POSIX-path sections have **never been run on a POSIX host** --
   see Section 7, which is the highest-value section for a Linux/macOS tester.
2. csb v0.7.1 installed; `dazzle-filekit>=0.4.2` present.
3. Real session history in `~/.claude/projects/`.

### Back up your index before starting

This checklist asks you to re-index, which **rewrites `folder_usage` for every
session**. Back it up first -- it is the only copy of your current numbers.

**cmd.exe**:
```cmd
copy "%USERPROFILE%\.claude\session-backup.db" "%TEMP%\session-backup.db.bak"
```

**PowerShell**:
```powershell
Copy-Item "$env:USERPROFILE\.claude\session-backup.db" "$env:TEMP\session-backup.db.bak"
```

**POSIX**:
```bash
cp ~/.claude/session-backup.db /tmp/session-backup.db.bak
```

### Working against a throwaway index (recommended)

Every command below accepts `--db`, so you can leave your real index alone:

**cmd.exe**: `set CSB_DB=%TEMP%\csb-checklist.db` then pass `--db %CSB_DB%`
**PowerShell**: `$env:CSB_DB = "$env:TEMP\csb-checklist.db"` then `--db $env:CSB_DB`
**POSIX**: `export CSB_DB=/tmp/csb-checklist.db` then `--db "$CSB_DB"`

The rest of this document writes `--db <your-db>` to mean "your real index or
the throwaway one". Cleanup is in the last section.

## High-Value Verification (~5 minutes)

If you only have five minutes, run these six. They are the reason this release exists.

### HV.1 -- A cross-repo session is findable at all

Validates: the entire point of #56. Before this release, a session that worked
in repo B while launched from repo A recorded only A.

- [ ] **Steps:**
  1. Re-index so tool paths are harvested: `csb update rebuild-index`
  2. `cd` into a repo you have worked on from a session launched **elsewhere**
  3. Run `csb scan .`
- [ ] **Expected:** the session appears. On v0.7.0 it did not.
- [ ] **Why this matters:** if this fails, nothing else in the release works.

### HV.2 -- The ranking names the place you actually worked

Validates: `usage_count` measures work units, not transcript length.

- [ ] **Steps:** `csb show <a session you remember well>`
- [ ] **Expected:** the top working directories are places you genuinely spent
  time. The launch directory should NOT dominate unless you really worked there.
- [ ] **Why this matters:** the old measure counted transcript events, so the
  launch folder won by construction. A plausible-looking-but-wrong ranking is
  the failure mode mocks cannot catch -- **you are the only oracle here.**

### HV.3 -- `-d` returns at least as much as `-D`

Validates: the match-gate removal, and the flag semantics generally.

- [ ] **Steps:** in any repo, run both:
  ```
  csb scan -d .
  csb scan -D .
  ```
- [ ] **Expected:** `-d` (folder + descendants) >= `-D` (this exact folder).
  **`-d` returning fewer than `-D` is a hard failure** -- it is arithmetically
  impossible for a correct implementation.
- [ ] **Why this matters:** this exact inversion is what the `--top` match-gate
  bug produced. It is the cheapest possible check for its return.

### HV.4 -- `--top` changes only what you see

Validates: display and matching are now separate questions.

- [ ] **Steps:**
  ```
  csb scan -d . --top 1
  csb scan -d . --all-folders
  ```
- [ ] **Expected:** **the session COUNT is identical**; only the number of
  folder lines per session differs.
- [ ] **Why this matters:** `--top` used to silently decide which sessions
  existed. A display flag must never change the answer to "what matched".

### HV.5 -- No junk in the folder list

Validates: the five precision rules, against your real transcripts.

- [ ] **Steps:** `csb show <a session with heavy shell use> --all`
- [ ] **Expected:** no `\dev\null`, no `NUL`/`CON`, no paths containing `$`,
  `*`, `%VAR%`, `{`, `[`, no bare drive letters (`C:`), no fragments that
  start mid-path (e.g. a bare `\claude\commits`).
- [ ] **Why this matters:** each of those appeared in real transcripts during
  development -- `2>/dev/null` ranked **#1 at 119 hits** under the naive
  approach. Your vault may contain a shape mine didn't.

### HV.6 -- Scope labels describe the search that ran

Validates: the `-D` label fix.

- [ ] **Steps:** run `csb scan -d .`, `csb scan -D .`, then `csb scan -D *`
- [ ] **Expected:** `-d` says "under <path>"; `-D` says "in exactly <path>";
  `-D *` says "(no descendants)". `-d *` and `-D *` must NOT print identical headers.
- [ ] **Why this matters:** when the two return different counts, the label is
  the only thing telling you why.

### HV.7 -- `-D` does not RETURN descendants either

Validates: the filesystem half of the query, which used to ignore `-D`.

The query has two halves. The SQL half always honored `-D`; the filesystem
half matches Claude Code's sanitized project-directory names by prefix, where
`C:\code` becomes `C--code` and therefore also matches `C--code-<child>`.

- [ ] **Steps:** pick a directory that has session-bearing *subdirectories*
  (e.g. `C:\code`), then compare the CLI against the index directly:
  ```
  csb scan -D "C:\code"
  ```
  ```
  python -c "import sqlite3,os;c=sqlite3.connect(os.path.expanduser('~/.claude/session-backup.db'));e={r[0] for r in c.execute('SELECT DISTINCT session_id FROM folder_usage WHERE folder_path=?',(r'C:\code',))};s={r[0] for r in c.execute('SELECT session_id FROM sessions WHERE start_folder=?',(r'C:\code',))};print(len(e|s))"
  ```
- [ ] **Expected:** the two numbers are **equal**. A CLI count higher than the
  index count means descendants are leaking back in.
- [ ] **Why this matters:** `-D` documents itself as "this folder only". It
  returned a session whose sole connection was a start folder one level below.

### HV.8 -- Every hint names a flag that actually works

Validates: three separate stale hints, all of which told users to type
something the parser rejects.

- [ ] **Steps:** run `csb show <id>` and `csb show <id> --filter min-work=50`,
  then **literally type whatever flag each hint suggests.**
- [ ] **Expected:** every suggested flag is accepted. In particular the
  low-value note must say `--all` (not `--all-folders`, which `show` does not
  have), and the thin-folder note must not suggest `--filter 0` (no longer
  valid syntax).
- [ ] **Why this matters:** a hint is an instruction. If it cannot be typed it
  is a bug, and this one shipped three times.

## Section 1: Migration and re-indexing (~5 min)

### 1.1 Schema v7 migrates without data loss

- [ ] **Steps:**
  1. Note your session count: `csb list -n 9999` (count the rows)
  2. Run `csb update rebuild-index`
  3. Count again
- [ ] **Expected:** same session count. Folder data changes; sessions do not disappear.
- [ ] **Check:** new columns exist.

  **cross-shell** (needs Python):
  ```
  python -c "import sqlite3,os;c=sqlite3.connect(os.path.expanduser('~/.claude/session-backup.db'));print([r[1] for r in c.execute('PRAGMA table_info(folder_usage)')])"
  ```
  Expect `path_exists` and `path_verified_at` present.

### 1.2 Migration is idempotent

- [ ] **Steps:** run `csb update rebuild-index` twice in a row
- [ ] **Expected:** second run succeeds; no "duplicate column" error.

### 1.3 Un-harvested sessions do not render as "zero folders"

Validates: `tool_paths_extracted_at` NULL means "unmeasured", not "empty".

- [ ] **Steps:** on a **fresh** index (before any rebuild), run `csb show <id>`
- [ ] **Expected:** folders reflect the old cwd-only data. Nothing claims a
  session touched zero folders.
- [ ] **Why:** "unmeasured" and "measured as zero" are different facts and must
  not look alike.

## Section 2: The display tiers (~5 min)

### 2.1 Three tiers render distinctly

- [ ] **Steps:** `csb show <an active session>`
- [ ] **Expected:**
  - Ranked **work locations** with counts
  - **"Also touched (no work credited)"** -- folders present but never a call's
    primary. These must NOT show a misleading `0x`.
  - A **collapsed low-value tier** summarizing scratch/unresolved paths
- [ ] **Check:** the collapsed tier states how many were hidden.

### 2.2 `--filter min-work=N` hides low-count folders but still reports them

- [ ] **Steps:**
  ```
  csb show <id>
  csb show <id> --filter min-work=5
  ```
- [ ] **Expected:** fewer folder lines, plus a note saying how many were hidden
  **and their total**. The aggregate must not silently vanish.
- [ ] **Why this matters:** a filter that hides data without saying so turns
  "I chose not to look" into "there was nothing there".

### 2.3 `--filter` rejects bad input loudly

- [ ] **Steps:**
  ```
  csb show <id> --filter 5
  csb show <id> --filter bogus=5
  csb show <id> --filter min-work=lots
  ```
- [ ] **Expected:** each fails with a message that names the valid keys.
  Nothing is silently ignored -- a filter that is quietly dropped returns a
  wrong answer that looks like a right one.
- [ ] **Check:** `--filter 5` (the pre-release syntax) must NOT be silently
  reinterpreted as `min-work=5`.

### 2.4 `--all` reveals the low-value tier

- [ ] **Steps:** `csb show <id> --all`
- [ ] **Expected:** scratch and unresolved paths become visible.
- [ ] **Note:** this is `--all`, deliberately NOT `--all-folders` (which means
  "no top-N truncation" on `list`/`scan`). Confirm both exist and mean
  different things -- if that reads as confusing to you, say so, that is a
  legitimate UX finding.

### 2.5 Scratch classification does not eat real projects

- [ ] **Expected:** a real repo named `tmpl-*`, `cache-*`, or `temporal*` is
  NOT classified as scratch. Matching is per-component and exact.
- [ ] **Check:** if you have such a repo, confirm it appears as a normal work
  location.

## Section 3: Scan flag semantics (~5 min)

### 3.1 `-d` vs `-D` on a discriminating path

The counts only differ when some session touched a **descendant but not the
folder itself**. Find one:

```
python -c "import sqlite3,os,collections;c=sqlite3.connect(os.path.expanduser('~/.claude/session-backup.db'));c.row_factory=sqlite3.Row;s=collections.defaultdict(set);[s[r['session_id']].add(r['folder_path']) for r in c.execute('SELECT session_id,folder_path FROM folder_usage')];a={f for fs in s.values() for f in fs};[print(p,len({k for k,v in s.items() if p in v}),len({k for k,v in s.items() if any(f.startswith(p+os.sep) for f in v)}-{k for k,v in s.items() if p in v})) for p in sorted(a) if p.count(os.sep)>=2 and {k for k,v in s.items() if p in v} and ({k for k,v in s.items() if any(f.startswith(p+os.sep) for f in v)}-{k for k,v in s.items() if p in v})][:5]"
```

- [ ] **Steps:** take a printed path P with counts `exact` and `desc-only`, then
  run `csb scan -d P` and `csb scan -D P`
- [ ] **Expected:** `-d` returns `exact + desc-only`; `-D` returns `exact`.

### 3.2 `-s` still means "originated here"

- [ ] **Steps:** `csb scan -s .`
- [ ] **Expected:** only sessions whose **start_folder** is here (or below).
  Should generally be far fewer than `-d .`, and must not be affected by
  tool-harvested folders.

### 3.3 Wildcard sibling-prefix expansion

- [ ] **Steps:** in a repo with siblings (e.g. `proj`, `proj-fork`), run
  `csb scan -d proj*`
- [ ] **Expected:** both siblings' sessions. Note that on cmd.exe/PowerShell the
  `*` reaches csb literally; on POSIX **quote it** (`'proj*'`) or the shell
  expands it first.

### 3.4 `-NI` bypasses the index (renamed from `-NU`, breaking)

- [ ] **Steps:** `csb scan -d . -NI`
- [ ] **Expected:** results come from walking `~/.claude/projects/` and reading
  transcripts, not from the index. In practice this matches on start folder,
  so typically far fewer results.
- [ ] **The old names are GONE, not aliased:** `csb scan -NU` and
  `csb scan --no-usage` must both fail with `unrecognized arguments`. A script
  using the old spelling should break loudly rather than change behavior.
- [ ] **`-s` becomes redundant under `-NI`:** `csb scan -s PATH -NI` and
  `csb scan -d PATH -NI` should return the same set, because `-NI` disables
  the query where `-s`'s restriction is applied.

### 3.5 `-NI` with `--deleted` explains itself

This combination can never match: deleted sessions exist only in the index,
and `-NI` bypasses the index.

- [ ] **Steps:** you need an index that actually contains a deleted session --
  the check is meaningless otherwise, and a real vault may have none. Confirm
  first:
  ```
  python -c "import sqlite3,os;print(sqlite3.connect(os.path.expanduser('~/.claude/session-backup.db')).execute('SELECT COUNT(*) FROM sessions WHERE deleted_at IS NOT NULL').fetchone()[0])"
  ```
  If that prints 0, build a scratch index with a deleted row and use `--db`.
- [ ] **Steps:** run `csb scan -D <path> --deleted` and then the same command
  with `-NI` added.
- [ ] **Expected:** the first finds the deleted session; the second finds
  nothing **and prints** `-NI cannot find deleted sessions -- they exist only
  in the index, which -NI bypasses. Drop -NI.`
- [ ] **Why this matters:** an impossible query should say why, not just
  return an empty list that looks like a real answer.

## Section 4: Precision rules against your own vault (~10 min)

This is the section most likely to find something new. The rules were derived
from one developer's transcripts; yours will differ.

### 4.1 Dump every folder your index now believes in

```
python -c "import sqlite3,os;c=sqlite3.connect(os.path.expanduser('~/.claude/session-backup.db'));[print(r[0]) for r in c.execute('SELECT DISTINCT folder_path FROM folder_usage ORDER BY folder_path')]"
```

- [ ] **Scan the list for anything that is not a directory.** Specifically:
  - [ ] Device names -- `NUL`, `CON`, `AUX`, `COM1`, `\dev\null` (Windows device
        names are **case-insensitive**: `nul` and `NUL` are the same device)
  - [ ] Shell metacharacters -- `$`, `*`, `?`, `%`, `{`, `[`
  - [ ] Bare drive roots -- a lone `C:`
  - [ ] Mid-path fragments -- e.g. `\claude\commits` with no drive or root
  - [ ] Doubled separators -- `C:\code\a\\b`
  - [ ] Git refs mistaken for folders -- `origin\main`, or a bare `s` from a
        `sed s/a/b/` expression
  - [ ] **Files stored as folders** -- anything `os.path.isfile()` says is a
        file. Includes extensionless ones (`VERSION`, `Makefile`, `LICENSE`,
        git hooks) and **dotfiles** (`.gitignore`). Check the *credited* tier
        especially: a measured run had 38 such entries, 30 of them ranked as
        working directories.
  - [ ] **Unresolved `..` or bare `.` components** -- these split one real
        folder's credit across two spellings, and one landed in the ranked tier.
  - [ ] **A colon past the drive spec** -- a colon-joined `PYTHONPATH` list, a
        pytest node id (`test_x.py::TestClass`), prose from a diagnostic `echo`.
  - [ ] **A leading `~`** -- unresolvable for a foreign transcript. Note that
        `PROGRA~1` is legitimate (the `~` is inside a component, not leading).
  - [ ] **(0.7.2) Bare words from relative `cd` targets** -- `-`, `..`, `foo`,
        or any single lowercase word. A literal `-` carried work credit in
        three real sessions before the fix.
  - [ ] **(0.7.2) Long dotfiles as folders** -- `.gitignore`, `.editorconfig`,
        `.gitattributes` as the FINAL component of a stored folder.
  - [ ] **(0.7.2) Backticks** -- ``C:\Users\X` `` (PowerShell escape absorbed
        into the match).
- [ ] **Expected:** none of the above.
- [ ] **Note on what is deliberately NOT filtered:** a single-letter final
      component (`D:\M` is a real directory with 429 measured work units), and
      paths that merely do not exist (a deleted repo is still where work
      happened). Flagging those would be a false positive.
- [ ] **If you find one:** that is a real finding. Capture the folder AND the
  command that produced it (search the transcript) and file it.

### 4.2 The `nul`-file nuance (Windows only)

Windows tools sometimes create a **literal file named `nul`** when a script
writes `> nul` from a POSIX-ish shell. That file is not addressable by Win32.

- [ ] **Expected:** `nul` never appears as a folder in the index regardless.
- [ ] **Note:** if you have such a file on disk, `dz delete-nul` removes it.

### 4.3 Relative-path resolution after `cd`

- [ ] **Steps:** find a session where you ran `cd <repo> && pytest tests/...`
- [ ] **Expected:** `<repo>\tests` is credited, not just `<repo>`. The `cd`
  target itself is deliberately demoted -- it says where the shell stood, not
  what the call operated on.
- [ ] **Check:** `<repo>` should still appear (as a touched folder, and as the
  primary for commands that named no path, e.g. `cd repo && git status`).

---

### 4.4 Drive-mapped POSIX spellings resolve

The file/directory probe only works if the filesystem is asked in a spelling
it understands. Windows cannot resolve `/d/M/x` or `/mnt/d/M/x`, so those used
to answer "nonexistent" and fall through to a lexical guess.

- [ ] **Steps:** find a session that ran a Git Bash or WSL command naming a
  file, e.g. `cp /d/M/.gitignore ...` or `cat /mnt/c/code/proj/VERSION`
- [ ] **Expected:** the *parent directory* is recorded, not the file.
- [ ] **Why this matters:** dotfiles are where this bites hardest, and no
  lexical rule can save you -- `.gitignore` is a file while `.git`, `.venv`,
  and `.github` are directories with an identical shape.

## Section 4b: `--filter KEY=VALUE` (~3 min)

### 4b.1 Valid syntax narrows and reports

- [ ] **Steps:** `csb show <id> --filter min-work=5`
- [ ] **Expected:** fewer folder rows, plus a note giving both the count and
  the total of what was hidden.

### 4b.2 Repeatable, ANDing

- [ ] **Steps:** `csb show <id> --filter min-work=5 --filter min-work=50`

### 4b.3 Bad input fails loudly

- [ ] **Steps:** try each of `--filter 5`, `--filter bogus=5`,

- [ ] **Expected:** each errors and **names the valid keys**. Nothing is

- [ ] **Why this matters:** a filter that is quietly dropped returns a wrong

## Section 4c: `--help` grouping (~2 min)

### 4c.1 Flags are grouped by the question they answer

- [ ] **Steps:** `csb scan -h`, `csb list -h`, `csb tree -h`
- [ ] **Expected:** titled sections for *selection*, *display*, and *limits*
  (plus *restore* on `scan`). `--top` and `--all-folders` appear under
  **display**, labelled as not affecting what matches.
- [ ] **Judgment call:** does the grouping actually help you find a flag
  faster? If a flag looks filed under the wrong heading, say so -- that is a
  legitimate finding even though every test passes.

### 4c.2 Mutual exclusion survived the regrouping

- [ ] **Steps:** `csb scan --top 3 --all-folders`, `csb scan -d . -D .`,
  and the same two on `list` / `tree`
- [ ] **Expected:** each is rejected with a "not allowed with" error.
- [ ] **Why this matters:** re-parenting a mutually-exclusive group into an
  argument group is easy to get wrong in a way that silently DROPS the
  exclusivity, leaving both flags accepted and one silently ignored.

## Section 4d: the 0.7.2 hardening (~10 min)

### 4d.1 -- A gone path still finds its history

- [ ] **Steps:** `csb scan -D <a folder you have deleted>` (any path with
  index rows; `csb show <session> --all` can suggest one)
- [ ] **Expected:** a warning (`does not exist on disk; searching the index
  anyway`) followed by real results. Before 0.7.2 this returned "No sessions
  found" WITHOUT querying -- in the flag whose purpose is finding history.
- [ ] With a term added (`csb scan -D <gone> <term>`): results stay
  path-scoped; it must NOT silently become a broad term search.

### 4d.2 -- No bare-word folders from relative cd

- [ ] **Steps:** dump distinct folders (Section 4.1 command) and look for
  `-`, `..`, or single lowercase words.
- [ ] **Expected:** none. `cd -` is discarded (unknowable); `cd ..`/`cd foo`
  resolve against the cwd.

### 4d.3 -- THE JUDGMENT CALL: is the cd-fact ranking still TRUE?

Primary credit now ranks by certainty: with an explicit `cd`, only paths the
move corroborates (under the target, or resolved relative to it) outrank the
target; absolute paths elsewhere in the command demote to presence.

- [ ] **Steps:** `csb show <a session you remember>` and judge the ranking
  against your memory, exactly as in HV.2.
- [ ] **Known, deliberate cost to weigh:** `cd repoA && python -c "...open
  file in repoB..."` now credits repoA. Measured example: a reference
  session's `~/.claude` credit went 20 -> 11 because sqlite queries against
  the DB were cd-prefixed. If this reads as WRONG for how you work, say so
  -- the remedy is weighted crediting (#57), and this checklist item is the
  evidence trigger.

### 4d.4 -- Nonexistent presence rows are hidden, not gone

- [ ] **Steps:** compare `csb show <id>` with `csb show <id> --all`.
- [ ] **Expected:** default "Also touched" holds only existing folders; the
  collapse line counts the hidden; `--all` reveals each with a reason
  (`(scratch)` / `(not found)`). A folder shown by `--all` must still be
  findable by `csb scan -D <it>`.

### 4d.5 -- `--filter` duplicates and negatives

- [ ] **Steps:** `--filter min-work=50 --filter min-work=5` and the reverse;
  then `--filter min-work=-5`.
- [ ] **Expected:** both orders act as 50 (strictest wins); the negative is
  rejected naming "non-negative".

### 4d.6 -- Quoted spaced paths harvest whole

- [ ] **Steps:** in a NEW session, run a command naming
  `"C:\Program Files\<something real>"` (quoted), then re-index and check.
- [ ] **Expected:** the full path appears; no `C:\PROGRAM` fragment is
  added. (Pre-0.7.2 fragments may persist as hidden presence rows -- they
  are nonexistent and collapse under 4d.4.)

### 4d.7 -- Help text no longer claims top-N matching

- [ ] **Steps:** `csb scan -h`
- [ ] **Expected:** the `-d` line reads "any recorded folder"; nothing in
  scan's help ties matching to `--top`.

### 4d.8 -- (rev 4) Quoted cd targets keep their spaces

The third pass's SEV-1: the quoting fix reached general extraction but not
the parallel cd-target parser, so `cd "C:\Program Files\App"` fabricated
base `C:\Program` -- which then WON primary as a "corroborated fact" while
the real target demoted to presence.

- [ ] **Steps** (pure-function, no index needed):
  ```
  python -c "from claude_session_backup import toolpaths as tp; print(tp._effective_base('Bash', {'command': 'cd \"C:/Program Files/App\" && dir'}, 'C:/launch'))"
  ```
- [ ] **Expected:** `('C:\\Program Files\\App', True)` -- the full target,
  never a fragment. Same for `pushd "..."`, `cd /d "..."`, single quotes,
  and a quoted POSIX path with spaces.
- [ ] **Why this matters:** a truncated base corrupts the entire cd-fact
  ranking -- the fragment takes the credit AND the real folder loses its
  corroboration. Second instance of the "fix applied at one call site,
  parallel site missed" pattern; check for a third.

### 4d.9 -- (rev 4) Error messages name what to TYPE

- [ ] **Steps:** `csb show <id> --filter min-work=lots`
- [ ] **Expected:** `expects a non-negative integer, got 'lots'` -- never a
  Python identifier like `_nonneg_int`.

### 4d.10 -- (rev 4) All-dots components are rejected before the probe

`C:\Users\...` (prose "et cetera" inside a command) was stored as a
VERIFIED-EXISTING worked folder: Win32 strips trailing dots, so the
existence probe resolved it to the real `C:\Users` -- the one measured junk
shape that defeats the existence safety net.

- [ ] **Steps:** dump distinct folders (4.1) and search for components of
  three or more dots.
- [ ] **Expected:** none. Interior dots survive: a real `a...b` or
  `release.v2` directory must NOT be rejected.

### 4d.11 -- (rev 4) Prominent scratch escapes the collapse, honestly

A scratch folder with more than 10 work units, or ranking in the session's
top 10, now surfaces in "Working directories" tagged `(scratch)`. Measured
motivation: one real session's #1 folder (its scratchpad, 207x) was
invisible behind "(N hidden)" -- and purge-prone scratchpads hold the
session's probe scripts and tools.

- [ ] **Steps:** `csb show <a session with heavy scratch use>` (e.g. one
  whose work built scripts in its scratchpad).
- [ ] **Expected:** the busy scratchpad appears in the ranked tier with its
  count and a `(scratch)` tag; routine low-count scratch stays collapsed;
  zero-work scratch NEVER escapes.
- [ ] The collapse note reports the hidden total ("N low-value paths
  hidden, M work units"); `--all` shows per-row counts, most-material
  first.
- [ ] **Judgment call:** does the promoted scratch row read as useful
  signal ("go rescue those scripts") rather than noise? This rule is
  user-specified; real-use feedback tunes it.

### 4d.12 -- (rev 4, user-found) Quotes protect every path spelling

Found by the user in their own vault: `D:\M\Software\_DeDRM (14x)
[not found]` -- the real directory is `_DeDRM, Proxies, Security, and
Scripts`, and 72 quoted Git-Bash spellings truncated at the comma because
the quoted pattern matched drive-letter form only. The third
parallel-site miss.

- [ ] **Steps:** find (or run) a command naming a quoted path with commas
  or spaces in EACH spelling -- `"C:\..."`, `"/c/..."`, `"/home/..."` --
  and a quoted RELATIVE form after a cd; re-index; check the folder list.
- [ ] **Expected:** full names, no fragments; the quoted-relative case
  credits the deep folder, not its first component.
- [ ] **Still true:** unquoted `see C:\a, C:\b` yields two paths -- the
  comma stays a prose boundary where no quote overrides it.
- [ ] **Why this matters:** the `[not found]` marker is the safety net
  that surfaced this -- when you see one on a folder you recognize as
  misspelled or truncated, that is the harvester asking you to report a
  shape it got wrong.

## Section 5: Existence hints (~3 min)

### 5.1 A deleted folder is still real history

- [ ] **Steps:** find a session that worked in a folder you have since deleted
  or renamed. `csb show` it.
- [ ] **Expected:** the folder is **still listed**. Existence is a confidence
  hint, never a filter.
- [ ] **Why this matters:** the transcript is a historical record. Hiding
  folders that no longer exist would erase exactly the history you keep backups for.

### 5.2 An unreachable network path does not hang or lie

- [ ] **Steps (if you have one):** index a session that worked on a UNC path or
  a disconnected mapped drive
- [ ] **Expected:** `csb show` returns promptly. An unknown result must not
  render as "missing" -- probe failure and confirmed absence are different facts.

## Section 7: POSIX hosts -- THE UNTESTED PLATFORM (~10 min)

**Highest-value section for a Linux/macOS tester.** Everything below has been
reasoned about but **never executed on a POSIX host**. An earlier revision of
the harvester rejected *every* POSIX path, meaning the feature silently produced
nothing on Linux and macOS while all tests passed. Pairs with issue #35.

### 7.1 POSIX absolute paths are harvested at all

- [ ] **Steps:** on Linux/macOS with real history, `csb update rebuild-index`
  then `csb show <id>`
- [ ] **Expected:** folders like `/home/you/code/proj` appear. **If the folder
  list is empty or cwd-only, that is the regression** -- report immediately.

### 7.2 The root allowlist covers your layout

A POSIX path is only accepted if it starts at a known root. Current list:
`home usr opt var tmp etc srv media mnt root proc sys bin sbin lib data work
workspace workspaces app apps code src projects repos Users Volumes private
scratch build storage`.

- [ ] **Expected:** your work roots are covered.
- [ ] **If you work under something else** (e.g. `/scratch2`, `/nfs`, `/data0`,
  a container mount), those folders will be **silently skipped**. Report the
  root -- this is under-harvesting by design, but the list should grow.

### 7.3 The single-letter-directory ambiguity

Known, accepted trade-off: a leading single-letter component is read as a
Windows drive, because that is how Git Bash (`/c/code`) and WSL (`/mnt/c/code`)
spell drives.

- [ ] **Steps:** if you have a genuine POSIX directory like `/e/project`, check
  how it is recorded
- [ ] **Expected (documented behavior):** it becomes `E:\project` -- **wrong on
  a real POSIX host.**
- [ ] **This is a known trade-off, not a surprise** -- but if it bites you in
  practice, say so. The design note says "revisit if a POSIX run reports it."
  **This checklist item is that report path.**

### 7.4 Case sensitivity

- [ ] **Expected:** `/home/you/Code` and `/home/you/code` are distinct folders
  on a case-sensitive filesystem and should not be merged.

## What the automated tests DON'T cover

- **Whether the ranking is TRUE.** Tests verify counting is consistent; only a
  human who remembers the work can say the top folder is the right one. This is
  the single biggest gap in the release.
- **Your transcripts' junk shapes.** The rules were tuned against one vault.
- **POSIX hosts** -- see Section 7. Never executed there.
- **Terminal rendering** -- codepage 437/1252, width, color, wrapping.
- **Real filesystem timing** -- unreachable network paths, permission errors.
- **Whether `--filter` / `--all` / `--all-folders` are distinguishable in
  practice.** Three similarly-named flags; only real use reveals confusion.
- **Whether re-indexing feels acceptably fast** on a large vault.
- **Cross-machine transcripts** -- a Linux-recorded session read on Windows.
