# v0.9.3 -- Epic -- session-sets completion (POSIX fences, epoch history, promotion, docs)

Hand-runnable companion to `tests/test_epochs_posix.py` (21), `tests/test_epoch_history.py` (29), and the R2/R3 additions across the set suites. Covers the overnight completion of the session-sets epic: `last` on POSIX, `last~N`/date addressing, boundary retention, promotion provenance, implicit `show`, and the precision boot-age headers.

**Legend** (external testers): "epoch" = the span between two machine restarts; "fence" = a boot/shutdown instant read from the OS; "boundary snapshot" = the exact open-at-shutdown roster the hook sweep freezes at each reboot; R2/R3/R4 = the release units of GitHub epic #68.

## Prerequisites

- csb at the version carrying this checklist (editable install reflects the working tree).
- For POSIX items: any WSL distro, Linux box, or VPS. For the full matrix, a systemd 254+ box (Ubuntu 24.04+) validates the journalctl JSON rung the design could only spec-freeze.

## 1. Epoch history on the real machine (R3)

- [ ] `csb set list` -- the Boot epochs table shows `boot` (in progress) plus up to five epochs with LOCAL times, causes, per-token commands, and the date-addressing footer.
- [ ] `csb set show last~1` -- header reads `Epoch 'last~1'`; roster is that epoch's sessions (or an honest empty message).
- [ ] `csb set show last~<beyond-your-depth>` -- pick N past what your OS log holds (this can be large: a dev box showed 58 real epochs; `last~999` is a safe probe) -- clear error naming how many epochs are known, exit 1.
- [ ] `csb set show <a date from the table>` -- resolves; if that date saw two restarts, csb lists both tokens and exits 2 (paste one to proceed).
- [ ] An EMPTY relative epoch falls through, disclosed: find one (deep history often has them) -- expect its `0 sessions` header, the dim "showing the nearest epoch with members" connector, then the settled epoch's full roster; `csb resume --set <that-token> <N>` addresses the roster you were shown. A DATE resolving to an empty epoch stays honestly empty (no fallthrough).
- [ ] `csb resume --set last~1 <N>` in a scratch-able terminal -- resolves the same session the show printed (abort at the prompt if it is a session you don't want opened).
- [ ] `csb set boot` / `csb set last~1` / `csb set <your-set-name>` -- implicit show works for all three shapes; `csb set list` still lists; `csb set -h` still helps.

## 2. Promotion with provenance (R3)

- [ ] `csb set new PROBE-EPOCH --from last~1` -- created; `csb set show PROBE-EPOCH` renders `promoted from 'last~1' (shutdown ...)`.
- [ ] `csb set show PROBE-EPOCH --json` -- `promoted_from.token == "last~1"`.
- [ ] `csb set new X --from garbage` -- exit 2, "takes a view".
- [ ] Cleanup: `csb set rm PROBE-EPOCH`.

## 3. POSIX fences live (R2)

Run inside WSL or on a Linux box (`python3 -m claude_session_backup ...` from the repo works without install; needs dazzle-lib):

- [ ] `csb set list` -- epoch table appears with REAL epochs from journalctl; causes are `unexpected`/`unknown`/`clean`, never a crash label on a rotated-wtmp box.
- [ ] `csb set show last` -- renders (roster may be empty on a box with no indexed sessions -- the header is the point).
- [ ] WSL semantics: the epochs listed are VM starts (short spans, `unexpected` causes) -- matches [platforms.md]'s WSL note, not a bug.
- [ ] On a box with neither journalctl nor `last`: the error names both rungs and says `current`/`boot` still work.
- [ ] **Deferred to real hardware**: systemd 254+ JSON shape (Ubuntu 24.04 VPS); a wtmp-rich box showing `clean` corroboration; any BSD.

## 4. Boundary retention (R3) -- needs real reboots over time

- [ ] After the NEXT reboot: `csb-live/boundaries/` gains a `boundary-<stamp>.json`; `csb set show last --open` badges exactly.
- [ ] After 6+ reboots (days later): only the newest 5 boundary files remain; `last~1 --open` still badges; beyond retention the flag reports honest absence.
- [ ] The Claude-less-reboot run: reboot 2+ times WITHOUT opening Claude Code, then open it and run `csb set show <the-working-epoch's-token> --open` -- the open-at-shutdown badges attach to the epoch where you actually worked, not the last empty one (read-time re-keying).
- [ ] `csb set show current` after each reboot: boundary sweep leaves the registry clean (no pre-boot ghosts).

## 5. Precision headers (polish)

- [ ] `csb set show current` / `boot` headers and the `set list` boot row all say `booted <N>d<N>h ago` -- the same vocabulary as row ages, so containment reads at a glance (a 12d-old row inside a `booted 12d19h ago` boot is visibly right).

## What the mocks don't cover (why this checklist exists)

- Real journalctl/wtmp output drift across systemd versions and distros -- the parsers were frozen against ONE real capture (systemd 249) plus specs.
- Local-timezone rendering against your actual TZ database (the `%z` colon splice).
- The multi-reboot retention arc (section 4) -- unobservable in any single test run.
- The feel of the ambiguity listing and the implicit-show ergonomics.
