# Human Test Checklist: `csb resume` on npm-shim installs

**Target version:** v0.6.3
**Ships with commit:** `v0.6.3: fix: resume resolves claude via which() -- npm-shim installs (#55)` (TBD -- pre-commit)
**Companion automated tests:** 2 new in `tests/test_commands.py` (which-resolved argv[0]; which-None error without spawn). Full suite: 1041 pass, 1 skipped.

## What this is

`csb resume` said `'claude' command not found in PATH` on npm-installed Claude Code (shims only, no `claude.exe`) while the same command line worked typed into the same shell -- bare-name `CreateProcess` searches PATH for `.exe` only and never applies `PATHEXT`. v0.6.3 resolves via `shutil.which()` and spawns the full path. A human runs this because launch behavior (TUI attachment, passthrough, install-method variants) is inherently end-to-end.

## Prerequisites

1. csb v0.6.3; a real resumable session in your index (`csb list -n 3`).
2. Know your install type: `where claude` (Windows) -- `.cmd` only = npm shim; `claude.exe` = native.
