# v0.9.5 -- Feature -- `csb setup update` + plugin drift detection (#75)

Hand-runnable companion to `tests/test_setup_update.py` (14 automated
tests). Verifies the two drift surfaces and the update wrapper on a real
machine -- including the one loop mocks cannot run: a REAL version gap
between the pip package and the installed plugin, closed by the wrapper.

**Legend** (for external testers): #75 = the GitHub issue this
implements; "the plugin" = the Claude Code plugin that ships csb's hook
scripts; "drift" = installed-plugin version != csb package version;
"the spec" = `claude-session-backup@dazzle-claude-session-backup`.

## Prerequisites

- csb at the version carrying this checklist (`csb -V` shows 0.9.5+).
- The plugin installed at an OLDER version than csb (this is the natural
  state right after `pip install -U` / a repo pull -- do NOT update the
  plugin before section 1).

## 1. The drift line on `csb status` (the surface that was missing)

- [ ] `csb status` -> a `Plugin:` line in yellow naming BOTH versions
      and the fix: `0.9.4 installed -- csb is 0.9.5; run csb setup update`.
- [ ] The line renders aligned with the other status labels (one label
      column throughout).
- [ ] Run any OTHER command (`csb list -n 3`, `csb backup --no-commit`):
      no drift mention anywhere. Drift reports where you look for state;
      it never nags ambient commands.

## 2. The setup checklist row

- [ ] `csb setup` (answer no/skip to any prompts you don't want) -> the
      closing checklist's `auto-backup plugin` row is `[ ]` with the
      version pair and `csb setup update` as its command line.

## 3. The wrapper closes the loop

- [ ] `csb setup update` -> prints `Installed plugin: <old>  (csb is
      <new>)`, runs the claude CLI's own update (its output is the
      progress UI), then `Updated: <old> -> <new>` and the no-restarts
      note.
- [ ] `csb status` again -> the `Plugin:` line is green `(current)`.
- [ ] `csb setup` again -> the plugin row is back to `[x]`.
- [ ] `csb setup update` once more -> `Already current: <new>`, exit 0.

## 4. Honest degradations

- [ ] In a shell where `claude` is NOT on PATH (or
      `set PATH=C:\Windows\system32` in a scratch cmd):
      `csb setup update` -> exit 3, stderr hands you the exact manual
      `claude plugin update <spec>` command.
- [ ] With a scratch `--claude-dir` that has no plugin cache
      (`csb setup update --claude-dir <empty-tmp>`): exit 3, both
      install commands printed (marketplace add + plugin install).

## What the mocks don't cover

- The REAL `claude plugin update` subprocess: its interactive output,
  exit codes, and how long it takes (the wrapper allows 120s).
- A real version gap: automated tests fabricate cache directories; only
  this checklist runs the actual drift -> update -> green cycle.
- Rendering: yellow/green/dim styling and label alignment in a real
  terminal.
- Whether the no-restarts claim HOLDS: after section 3, an already-open
  session's next hook fire should run the NEW plugin's scripts (check
  `<claude-dir>/csb-logs/` for the fresh fire).
