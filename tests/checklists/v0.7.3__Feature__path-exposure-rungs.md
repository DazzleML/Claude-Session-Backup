## What this is

`csb show --paths <level>` exposes harvest confidence as selectable rungs on
a `dazzle_lib.continuum.Continuum` -- csb is deliberately that module's first
consumer outside dazzlecmd's orbit (the canary role). Selecting a level shows
it and everything colder:

| rank | level | shows |
|---|---|---|
| -3 | `cd` | only folders the shell provably stood in (needs v8 provenance) |
| -2 | `verified` | + folders the existence probe confirmed |
| -1 | `approximated` | + unverifiable leaves FOLDED into their nearest existing ancestor, counts merged, marked `(~)` |
| 0 | `suspected` | everything stored, as extracted -- **the default** |
| +1/+2 | `junk` / `raw` | declared, unpopulated -- honest note |

Two things only a human can judge here: whether the **fold tells the truth**
on a vault you remember, and whether the **vocabulary reads well** enough to
live in muscle memory. Both are explicitly MANUAL items below.

## Prerequisites

1. csb v0.7.3; `pip show dazzle-lib` >= 0.8.2.
2. Real session history; **run `csb update rebuild-index` once** (stamps
   provenance -- the `cd` rung is honestly empty before that).
**Config isolation (adopted from the first tester pass -- strictly
better than write-then-reset):** for every step that sets `csb config`
values, use `--claude-dir <scratch-dir>` so config writes land in an
isolated dir and your live config is never touched; combine with
`--db <real db>` for read-only index access. No reset step needed. If
the purge-countdown line matters to a comparison, copy `settings.json`
into the scratch dir (it is read from claude-dir).

**Revision 2** (first tester pass: HOLD -> fixed same-day): the fold
fabricating a `\` ancestor for driveless rows (HV.3/Section 3 now pin
it), the `(~)` marker missing from the touched tier in both renderers,
and lossy float config values coercing silently.

**Revision 3** (second pass, targeted attack on the fixes: HOLD -> fixed
same-day). The fold held under all 8 adversarial angles (deep chains,
not-verified intermediates walked past, drive-relative oddities). Two
new fixes: the round-1 float patch itself crashed on a stored `Infinity`
(uncaught OverflowError -- now caught and warning), and boolean `true`
slipped every numeric check to silently become threshold 1 (now warns).
Judgment call decided: the low tier was a FIFTH marker-blind render
site; the `(~)` convention now covers all three tiers. See HV.6b.

3. Back up your index first (it is the only copy of your numbers):
   - **cmd.exe**: `copy "%USERPROFILE%\.claude\session-backup.db" "%TEMP%\sb.bak"`
   - **PowerShell**: `Copy-Item "$env:USERPROFILE\.claude\session-backup.db" "$env:TEMP\sb.bak"`
   - **POSIX**: `cp ~/.claude/session-backup.db /tmp/sb.bak`
   Scratch alternative: every command accepts `--db <path>`.

## High-Value Verification (~6 minutes)

### HV.1 -- The superset chain on your real data

Validates: the fall-through arithmetic (one rank comparison, no lookup table).

- [ ] **Steps:** `csb show <id> --paths X` for X in `cd`, `verified`,
  `approximated`, `suspected`; compare the Working-directories sets.
- [ ] **Expected:** each colder view is a subset of the warmer
  (`approximated` may RENAME rows upward -- `(~)` -- but never invent a
  place that appears from nowhere).
- [ ] **Scripting warning (measured):** csb wraps long paths across console
  lines. A naive line-parser produced a FALSE FAIL during development.
  Parse wrapped output carefully or query the DB directly.

### HV.2 -- Default is byte-identical to 0.7.2

- [ ] **Steps:** `csb show <id>` vs `csb show <id> --paths suspected`
- [ ] **Expected:** identical -- shipping the feature changes nothing until
  someone moves the dial. If ANY unflagged output differs from 0.7.2, that
  is a hard failure.

### HV.3 -- The fold heals, conserves, and marks

Validates: `approximated` as a TRANSFORM (the one rung that is not a filter).

- [ ] **Steps:** `csb show <id> --paths approximated` on a session with
  `[not found]` leaves whose parents exist (the `.manifest` case, the
  `MoonshotAI\a` case).
- [ ] **Expected:** leaves fold upward; counts MERGE into the ancestor; the
  row carries `(~)`; a foreign path with no reachable ancestor stays put
  unfolded.
- [ ] **The conservation law:** total work units in the approximated view ==
  total in the suspected view. This is the axis invariant made auditable;
  any leak is a SEV-1.
- [ ] **MANUAL, the important one:** does the folded ranking still read TRUE
  against your memory of the session? A fold that conserves counts but
  lands them on the wrong ancestor passes every automated check.

### HV.4 -- Matching is rung-blind, permanently

- [ ] **Steps:** `csb config paths_level cd`, then
  `csb scan -D <a gone folder with index rows>` and `csb search <term>`.
- [ ] **Expected:** both find everything they found before -- display
  condensation never shrinks matching. (Structural guarantee: the query
  layer cannot import the rung module; a test greps for it.)
- [ ] Reset: `csb config paths_level suspected` (or remove the key).

### HV.5 -- `cd` provenance is real after rebuild

- [ ] **Steps:** after `rebuild-index`, `csb show <id> --paths cd`
- [ ] **Expected:** the folders the session's shell actually stood in --
  launch dir and cd targets -- and nothing extracted-only. Cross-check one
  entry against your memory or the transcript.
- [ ] On an index NOT yet rebuilt: `--paths cd` is empty-but-honest, never
  wrong-but-plausible.

### HV.6 -- Loud failures everywhere

- [ ] `csb show <id> --paths bogus` -> names all valid levels.
- [ ] `csb config paths_level bogus` then `csb show <id>` -> warns naming
  the key, falls back to `suspected`, still renders.
- [ ] `csb config scratch_escape_min_work lots` -> warns naming the key,
  uses 10, still renders.

---

### HV.6b -- (rev 3) config pathologies never crash

- [ ] `csb config scratch_escape_min_work Infinity` then `csb show <id>`
  (scratch claude-dir!): warns naming the key, uses 10 -- NEVER an
  OverflowError traceback. Same for `-Infinity`, and for
  `scratch_escape_top_rank`.
- [ ] `csb config scratch_escape_min_work true`: warns (a bool is not a
  count); never silently becomes threshold 1.
- [ ] A zero-work fold onto a scratch ancestor (`--paths approximated
  --all`): the low-tier row carries `(~)` like every other tier.

## Section 1: Reserved rungs and the alias (~2 min)

- [ ] `--paths junk`, `--paths raw`, `--paths all`: each succeeds WITH the
  not-yet-populated note -- never an error, never silently identical to
  `suspected` without the note.

## Section 2: Config precedence and the F1 knobs (~4 min)

- [ ] Flag beats config: `csb config paths_level cd` +
  `csb show <id> --paths verified` -> verified view.
- [ ] Config beats default: bare `csb show <id>` -> cd view. Reset after.
- [ ] `csb config scratch_escape_min_work 3` -> a 4-unit scratch folder now
  escapes to the ranked tier `(scratch)`; reset to 10 and it collapses
  again. Same exercise for `scratch_escape_top_rank`.

## Section 3: Fold edge cases (~5 min)

- [ ] A folded row landing on a folder that ALREADY had its own row: one
  row, counts summed, `(~)` present.
- [ ] Fold + scratch interplay: if the nearest existing ancestor is a
  scratch dir (e.g. `%TEMP%\...`), the folded row then obeys the normal
  scratch rules (escape only when prominent). No double-display.
- [ ] `[start]` marker: a fold must never move the start-folder marker onto
  an ancestor it does not belong to.
- [ ] UNC / other-drive leaves with no reachable ancestor: stay unfolded,
  visible per their own tier rules.

## Section 4: The canary role (~3 min, maintainers)

- [ ] `pip show dazzle-lib` -- version and whether the local editable tree
  or a wheel is resolving. csb's canary tests
  (`tests/test_continuum_canary.py`) are the early-warning line for
  continuum churn: after any dazzle-lib upgrade, run them FIRST.
- [ ] The ranks-are-ints test doubles as the `densify_between`/Fraction
  landmine guard -- if csb ever needs a new rung, DECLARE it in
  `pathlevels.py`; never densify at runtime.

## Section 2b: composition with --filter (~2 min)

The folder display is a fixed pipeline: `--paths` view -> tiering (scratch
escape) -> `--filter min-work` -> render. The order is load-bearing.

- [ ] **Steps:** find (or scratch-build) a session where two missing leaves
  fold into ONE ancestor; run
  `csb show <id> --paths approximated --filter min-work=<sum>`
- [ ] **Expected:** the MERGED count passes the threshold (fold first, then
  filter). `min-work` asks how much work happened HERE, and the rung view
  is what defines "here".
- [ ] `csb show -h` states the pipeline, the defaults, and the ordering.

## Section 5: Cross-verb quiet (~2 min)

- [ ] `csb list`, `csb scan`, `csb tree`: no `--paths` flag exists there
  (deferred by design -- see the DWP Decision Ledger), output unchanged
  from 0.7.2, help text unchanged.
- [ ] **Scan is deliberately rung-free in BOTH directions:** its matching
  is structurally rung-blind (the query layer cannot import pathlevels),
  and `paths_level` config must NOT alter scan output -- scan sits at the
  `suspected` default by construction, and no config knob may silently
  change what it returns.

## What the automated tests DON'T cover

- **Whether the fold's ancestors are the RIGHT ancestors** on your vault
  (HV.3's MANUAL item) -- conservation can pass while geography is wrong.
- **Vocabulary feel**: `cd / verified / approximated / suspected` -- do the
  names survive real use? Long-form aliases are a deferred option; muscle-
  memory feedback is the trigger.
- **The `(~)` marker's legibility** in real terminals, cmd.exe included.
- POSIX behavior (untested platform, pairs with #35).
- A real dazzle-lib version bump flowing through the canary suite.
