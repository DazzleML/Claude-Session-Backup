## Anomaly (run 1, root-caused before trusting any verdict)

The first run reported 6 `apply-failed` ("found 0 occurrences") — **every multi-line mutant**, while all single-line mutants applied. Root cause: the target file is pure CRLF on disk and the harness matches raw bytes (deliberately, for byte-exact restore verification), while the generator emitted `\n`-joined patterns. Fix: the spec's multi-line `original`/`mutated` strings were converted to `\r\n`. Run 2 applied 12/12 with zero anomalies. Lesson for future specs on this repo: **multi-line mutants must be CRLF-encoded**, and a pre-validation that uses `read_text()` (which normalizes newlines) will falsely pass what the harness rejects.
